## Подключение VM runner и очистка инфраструктуры

Отдельный job `setup-vm-runner-connectivity` перед основным plan восстанавливает временные Private Endpoint раннера и ожидает распространения DNS. Для этого выполняется целевой plan/apply только сетевых зависимостей — без refresh секретов, который требует уже работающего доступа к закрытому Key Vault. Перед полным удалением инфраструктуры доступ также восстанавливается.

После публикации cleanup выполняет обычный plan/apply с `enable_runner_endpoints=false`: удаляются только временные endpoints и ожидания DNS, DNS-записи обновляются с сохранением адресов постоянных endpoints. Секреты, Function App и provisioning таблиц больше не зависят от временных endpoints. State остаётся под управлением Terraform; скрипты и ручное удаление Azure-ресурсов не используются. Значение по умолчанию `enable_runner_endpoints=true` применяется при основном деплое. Запуски CI, release и destroy для одного окружения выполняются последовательно.

После прежнего ошибочного cleanup нужно повторно запустить release с исправлениями, чтобы восстановить секреты и приложение.

Проверка конфигурации без доступа к Azure: `terraform validate` из `src/infrastructure`.

## Нормализация сообщений

AI получает исходный текст сообщения вместе с текстом, извлечённым из изображения. Для SHA-256 и новых записей SpamHistory используется очищенный текст:

- Unicode NFKC и нижний регистр без зависимости от текущей культуры;
- удаление пробелов, эмодзи, невидимых форматирующих символов и селекторов вариантов;
- замена последовательностей Unicode-цифр на один маркер `х`, независимо от длины числа;
- сохранение букв разных языков, диакритики и прочей пунктуации. Подмена букв цифрами отдельно не нормализуется.

Например, `Предлагаю 1000 рублей доход` и `предлагаю 🔥 10001 рублей доход` имеют одинаковый хеш. Полностью очищенные до пустой строки сообщения проверяются AI без чтения или записи кеша хешей, чтобы не объединять разные сообщения из одних эмодзи.

Старые хеши и записи истории автоматически не мигрируют: варианты сообщений с новым хешем сначала проверяются AI, после чего кеш пополняется в новом формате.
